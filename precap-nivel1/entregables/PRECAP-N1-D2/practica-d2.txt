PREDICCION BLOQUE A:

¿Qué pasa si haces docker run nginx dos veces seguidas sin --name?
Se crean dos contenedores independientes. Aunque ambos utilicen la misma imagen de Nginx, cada uno tendrá un ID único y un nombre aleatorio distinto.

Si eliminas un contenedor con docker rm, ¿la imagen nginx sigue en tu máquina?
Sí, la imagen permanece intacta.

¿Puedes entrar a un contenedor que está detenido con docker exec -it?
No. El comando docker exec sirve para ejecutar un proceso nuevo dentro de un contenedor que ya está en ejecución. Si el contenedor está detenido, no hay un entorno activo donde correr ese comando.

PREDICCIONES bloque B:
¿Qué pasa si dos contenedores en redes Docker diferentes intentan hacer ping por nombre?
El ping fallará. Por lo general, las redes en Docker están aisladas.

Si eliminas el volumen con docker volume rm mientras el contenedor que lo usa está corriendo, ¿falla o borra?
El comando fallará. Docker protege los datos activos y te mostrará un mensaje de error indicando que el volumen está en uso.

¿Qué ocurre si mapeas el mismo puerto del host dos veces? Ej: -p 8080:80 en dos contenedores distintos.
El segundo contenedor no iniciará. Un puerto del host solo puede ser escuchado por un proceso a la vez; si necesitas ambos, tendrías que mapear el segundo a un puerto distinto en el host.
